# Постоянная установка: подпись расширения

## Что такое AMO и зачем это нужно

**AMO** — addons.mozilla.org, официальный каталог дополнений Mozilla и
одновременно сервис подписи. Firefox и все его форки (включая Zen) отказываются
устанавливать расширение навсегда, если файл `.xpi` не подписан криптографическим
ключом Mozilla. Настройка `xpinstall.signatures.required` в релизных сборках
и в Zen не работает — обойти проверку нельзя.

Важно: подпись и публикация — **разные вещи**. У AMO два канала:

| | `listed` | `unlisted` |
|---|---|---|
| Видно в каталоге addons.mozilla.org | да | **нет** |
| Проверка | автоматическая + человеком | только автоматическая |
| Сколько ждать | дни | минуты |
| Кто раздаёт обновления | AMO | вы сами |

Нам нужен **`unlisted`**: расширение остаётся приватным, никто его не найдёт
поиском, но подпись настоящая и расширение ставится навсегда. Именно этот канал
уже прописан в `package.json` и в CI.

**API-ключи** — пара «логин/пароль» для автоматизации, чтобы не загружать zip
руками через сайт. Состоит из:

- **JWT issuer** — идентификатор вида `user:18294746:492`;
- **JWT secret** — 64 шестнадцатеричных символа.

## Часть 1. Получить ключи (делается один раз)

1. Зарегистрируйте или войдите в аккаунт Mozilla: <https://accounts.firefox.com/>.
   Подойдёт ваш `avatar_game@outlook.com`.

2. Откройте **<https://addons.mozilla.org/developers/>**. При первом входе
   появится **Firefox Add-on Distribution Agreement** — примите его,
   иначе API работать не будет.

3. Перейдите на **<https://addons.mozilla.org/developers/addon/api/key/>**
   (то же самое: в шапке **Tools → Manage API Keys**).

4. Нажмите **Generate new credentials**.

5. AMO пришлёт на почту письмо со ссылкой подтверждения. **Пока вы по ней не
   перейдёте, ключи не появятся.** Если письма нет — проверьте спам и
   обновите страницу после перехода.

6. После подтверждения страница покажет:

   ```
   JWT issuer   user:18294746:492
   JWT secret   3f7a…（64 символа）
   ```

   **JWT secret показывается ровно один раз.** Скопируйте его сразу в менеджер
   паролей. Если потеряли — не страшно: нажмите **Revoke** и сгенерируйте новую
   пару, старая перестанет работать.

> Ключи дают право публиковать версии ваших дополнений. Никогда не коммитьте их
> в репозиторий — даже в приватный.

## Часть 2. Подписать локально (Windows, cmd)

Один раз установите зависимости:

```
cd E:\home\projects\web\mdloader
npm install
```

Затем при каждой подписи:

```
set WEB_EXT_API_KEY=user:18294746:492
set WEB_EXT_API_SECRET=3f7a…
npm run sign
```

В PowerShell синтаксис другой:

```powershell
$env:WEB_EXT_API_KEY    = "user:18294746:492"
$env:WEB_EXT_API_SECRET = "3f7a…"
npm run sign
```

`set` действует только в текущем окне консоли — при следующем запуске
переменные нужно задать заново. Это и хорошо: ключи не оседают в системе.

Что произойдёт: `web-ext` упакует папку `extension/`, загрузит на AMO, дождётся
автоматической проверки (обычно 1–3 минуты) и скачает подписанный файл в
`artifacts\librezam-modified-1.2.0.xpi`. Папка `artifacts/` в `.gitignore`.

## Часть 3. Установить .xpi в Zen

1. Откройте `about:addons`.
2. Шестерёнка справа сверху → **Install Add-on From File…**
3. Выберите `artifacts\librezam-modified-1.2.0.xpi`.
4. Подтвердите запрошенные разрешения.

Расширение установлено навсегда и переживает перезапуски браузера.

**Проверьте после установки:** ID расширения должен остаться
`mdloader@dodecube`, иначе нативный хост его не узнает. Если связь не работает,
перезапустите регистрацию хоста:

```
python native-host\install_firefox_host.py
```

## Часть 4. Автоматизация через GitHub Actions (по желанию)

Чтобы не подписывать руками, положите ключи в секреты репозитория:

```
gh secret set AMO_JWT_ISSUER
gh secret set AMO_JWT_SECRET
```

Обе команды спросят значение скрыто — ключи не попадут в историю консоли.
Проверить: `gh secret list` (покажет только имена, значения GitHub не выдаёт
никому, включая вас).

Дальше подпись запускается тегом:

```
git tag v1.2.1
git push origin v1.2.1
```

Workflow `.github/workflows/release.yml` подпишет сборку и приложит `.xpi`
к GitHub-релизу — скачиваете и ставите.

## Обновление на новую версию

**Номер версии на AMO расходуется навсегда.** Повторно подписать `1.2.0`
нельзя даже после удаления. Перед каждой подписью поднимайте версию:

1. В `extension/manifest.json` — поле `version`, например `1.2.0` → `1.2.1`.
2. Желательно то же значение в `package.json`, чтобы не путаться.
3. Подписать заново и установить поверх — Zen обновит расширение,
   сохранив очередь и настройки.

Автообновления у самораздаваемого расширения не будет: Firefox не знает,
откуда брать новые версии. Чтобы включить их, нужен `update_url` в манифесте и
файл `updates.json` на любом статическом хостинге (подойдёт GitHub Pages). Для личного
использования проще ставить новый `.xpi` вручную.

## Если что-то пошло не так

| Ошибка | Причина и решение |
|---|---|
| `401 Unauthorized` | Неверный или отозванный ключ; часы на машине сильно расходятся с реальным временем (JWT живёт 5 минут) |
| `Version already exists` | Поднимите `version` в `extension/manifest.json` |
| `You must accept the agreement` | Зайдите на addons.mozilla.org/developers/ и примите соглашение |
| Ключи не появляются после Generate | Не перешли по ссылке из письма-подтверждения |
| Расширение ставится, но хост не отвечает | ID в манифесте ≠ `allowed_extensions` в манифесте хоста; перезапустите `install_firefox_host.py` |
| `web-ext: command not found` | Не выполнен `npm install` в корне репозитория |
